2026-11-18 대표 결정: 파트장 PC마다 구성 파일을 옮기기 번거롭다며 "지침 다 공유해도 괜찮아", 공개 포크에 올리되 **대표 실명만 빼기**를 골랐다(비공개 저장소안은 파트장 GitHub 계정이 필요해 안 고름). 포크가 공개라 누구나 보고 기록이 남는다는 점은 알린 뒤 고른 것이다.

- 파일: 포크 `shared/company-org.json`. 대표 실명 "이재영"(상담사 메일 발신자 호칭·관리자 화면 담당자 필터, 6곳)은 `{{담당자 이름}}` 자리 표시로 바뀌어 있다.
- **배포(대표 결정 "최소한의 유지보수, 링크만 던지면 바로 업데이트"):** 대표가 "배포해줘"·"회사 구성 Git에 올려줘"라고 하거나 부서·지침을 바꾼 뒤에는 대표 PC 프로그램 폴더에서 `npm run office:release`를 쓴다(실명은 `.office/release.json`에 기억해 둠, 첫 실행 eb5da33 때 `--name`으로 저장). 공유 구성 갱신·커밋·포크 main push 뒤 "파트장님께 보낼 문구"(`"https://github.com/Lupus-01/ai-office 최신 버전으로 업데이트해줘"`)를 출력하니 그대로 대표에게 전하고 CI를 확인한다. 코드 변경은 검사·커밋을 마친 뒤 이 명령으로 올린다.
- 파트장 PC 업데이트: 그 문구를 터미널 AI에게 말하면 `npm run office:update`(fast-forward·필요 시 npm ci·서버 재시작·공유 구성 맞춤). 고친 파일·로컬 커밋·진행 중 업무가 있으면 거부한다. 이 명령은 eb5da33부터라, 그 전에 설치한 PC는 한 번은 AI가 git pull 방식으로 받는다.
- **올리기 전 실명 점검:** publish는 메일·휴대폰·사용자 경로·지정한 이름만 막는다. 지침 속 예시 문장의 상담사 이름은 못 막는다. 2026-11-18 상담사영상부 지침의 예시 "백범기 선생님은…"을 대표 구성에서 가상 예명 '가상별'로 바꿨다(구성 백업 `.office/org-backup-2026-11-18-before-mask.json`). 올릴 때마다 `선생님|상담사님|예:` 주변을 훑는다.
- 파트장 PC: 설치 때 AI가 묻고 `apply --name <파트장 이름>`. 이후 서버를 켤 때 공유 파일이 바뀌면 자동으로 다시 맞춘다(파트장이 고친 구성은 덮어씀). 대표 PC는 표식이 없어 자동 적용 안 됨.
- 같이 안 가는 것: 예약, 계정 로그인, 보관함 자료(정책 지식창고·상담사 원본·수집 도구·프로필 양식). 그래서 홍카페정책부·상담사데이터자산화부·상담사영상부·프로필제작부는 파트장 PC에서 그대로는 일하지 못한다.
- 이 기능 전에 만든 수동 전달용 파일(바탕화면 `AI오피스-회사구성-2026-11-18.json`, 실명·예시 이름 포함)은 대표 지시로 같은 날 지웠다.

**Why:** 공개 저장소에는 실제 상담사·고객 개인정보를 올리지 않는다는 원칙과 대표의 공유 결정을 함께 지키기 위해서다.

**How to apply:** 회사 구성을 다시 올릴 때 위 순서와 실명 점검을 따른다. 관련: [[windows-test-setup]], [[workspace-backup-repo]].
