대표가 2026-11-24에 두 번 말했다: "전반적인 업무 진행속도가 안 나오는 것도 문제", "계속 딜레이 되고 작업이 늦어지는 게 확실히 있다, 이렇게 진행되면 사람이 하는 게 더 빠르다". 속도는 정확도와 같은 급의 요구다.

**Why:** 상담사 메일 3명 준비 14분 중 12분이 검수 반복이었고, 꼬리별 글 10·댓글 20은 검수 4회 반복에 22분, Aside 게시가 건당 2~4분(30건이면 80분 이상)이었다. 내가 Aside 대기(1시간)에 걸린 업무를 확인하지 않고 밤새 기다려 15시간이 지나기도 했다.

**How to apply:**
- 지연 원인(실측): ① 품질검수·검증실이 문체·문장 틀 겹침으로 여러 번 반려 ② Aside 직원이 화면을 보며 판단하는 조회·게시(건당 분 단위) ③ 권한·연결 문제로 멈춘 실행을 늦게 발견.
- 고친 것: 회사 규칙에 "속도 규칙"(반려 업무당 최대 1회, 문체·틀·취향은 반려 사유 아님, 재검수 단계 추가 금지). Aside 게시·발송은 `--effort low`·대기 10분(f25583b, 효과는 아직 실측 전). 상담사 메일은 수집 도구·연결 계정 발송으로 바꿈([[counselor-analysis-mail]]).
- 업무를 넘긴 뒤 기다릴 때: 10분 안에 끝나지 않으면 `events.jsonl`로 단계별 시간과 `aside session list`의 suspended를 본다. 같은 단계가 반복되거나 멈춰 있으면 바로 원인을 본다. 기다리기만 하지 않는다.
- 실행 중인 업무가 있을 때 서버를 재시작하지 않는다(게시가 끊겨 결과가 불확실해진다). 코드 변경은 업무가 끝난 뒤 적용한다.
- 대표에게 시간을 말할 때는 실측만 말한다. 11-23에 꼬리별이 "9~11분"이라고 한 것은 일부 실행만 본 값이라 틀렸다(30건 전체는 1시간 이상).
- 남은 개선 후보(대표 결정·개발 필요): 네이버 카페 공식 API 연결(글은 초 단위, 대표 동의 클릭 필요. 댓글은 API 없음), 댓글을 Aside repl로 AI 없이 넣는 방식 개발.
