- **"PR해줘":** 검증, 변경 내용 검토, 커밋, 푸시, PR 생성, CI 확인, 결과 보고까지 한다. 머지하지 않는다.
- **"머지해줘":** 머지 직전 재확인, 머지, 기준 브랜치 동기화, 해당 작업 브랜치 삭제까지 한다. 브랜치 삭제를 다시 묻지 않는다.
- **"PR하고 머지까지 해줘":** 위 두 가지를 한 번에 한다.

- **PR 대상:** 지정이 없으면 포크(`origin`, `Lupus-01/ai-office`)의 `main`으로 보낸다. 원본(`upstream`)에는 대표가 따로 말할 때만 보낸다.
- **원본 main 직접 push(2026-11-09):** 원본 개발자가 "웬만한 작업은 main에 바로 push"하라고 했고, 대표가 따르기로 했다(첫 적용: 6837b47). 순서: upstream 최신 fetch → fast-forward 가능할 때만 push(강제 push 금지, 원본이 앞서 있으면 그 위로 다시 쌓고 재검증) → 전체 검사(브라우저·화면 변경이면 verify:browser·verify:ui) 통과 후 push → push 뒤 CI 확인. 안전 규칙(외부 발송 확인·계정 정보), 카톡 발송 같은 큰 새 기능, 회사 설정 저장 형식 변경은 PR을 권하고 대표에게 먼저 묻는다.

**Why:** 2026-11-05 대표가 이 기준을 채택했다. 혼자 쓰는 저장소도 머지는 따로 지시하기로 확인했다. 머지는 되돌리기 어렵고, 같은 AI가 쓰고 검토하고 머지하면 사람이 확인할 기회가 없어진다. 대표는 포크를 혼자 쓴다.

**How to apply:** [[personal-ai-workflow-skills]]의 pr-lifecycle 스킬이 "PR해줘"를 머지까지로 해석하는 문구보다 이 기준을 우선한다. `gh`로 만들 수 없어 링크를 드릴 때는 대표가 버튼을 눌러야 PR이 생기므로, 그 상태에서 PR 생성 완료로 보고하지 않는다. 포크 `main`에 머지하면 원본과 어긋나 이후 원본을 받을 때 충돌이 날 수 있으므로, "머지해줘" 전에 그 영향이 있으면 알린다.
