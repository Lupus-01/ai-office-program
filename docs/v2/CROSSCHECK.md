# 1.0 ↔ 2.0 교차검증 (2026-11-25)

1.0 기준 코드(`main` `d4ef6a7`, 별도 폴더에 펼침)와 2.0 코드(`v2-dev`)를 같은 조건으로 나란히 돌린 결과다. 운영 중인 1.0(4777, `~/AIOffice`)과 대표가 보는 개발 서버(4790)는 건드리지 않았다. 가상 구성·가상 자료만 썼고 외부 발송은 없다.

## 1. 자동 검사

| 확인 | 1.0 기준 코드 | 2.0 코드 |
| --- | --- | --- |
| 전체 테스트(`npm run check`) | 663개 중 654 통과·실패 4·건너뜀 5 | 713개 중 704 통과·실패 4·건너뜀 5 |
| 실패 4건 | 이 PC의 환경 문제(심볼릭 링크 1, codex 인자 2, Codex 기본 모델 1) | 같은 4건 |
| **1.0 원본 테스트 663개를 2.0 코드에 그대로 실행** | — | 653 통과. 새 실패 1건은 "화면 탭 4개" 검사(2.0에서 탭 구성을 바꿔 의도한 차이) |

## 2. 코드 대조

`dashboard/orchestrator.mjs`·`runner.mjs`·`lib/ai-judge.mjs`·`browser-work.mjs`·`schedules.mjs`·`continuous.mjs`의 변경 줄을 읽었다. 기존 경로의 동작이 달라진 곳은 두 가지이고 둘 다 의도한 변경이다.

- 업무 예산을 다 쓰면 새 AI 호출을 시작하지 않고 계속할지 묻는다(1.0은 병렬 단계가 한도를 넘겨 시작할 수 있었다).
- 같은 발송 문안 형식 오류가 고친 뒤에도 되풀이되면 자동 반려를 멈추고 묻는다.

나머지는 덧붙인 것이다(순번 접수표, 호출 원장, 묶음 예산, 대조함 결정 반영). 1.0에서 시작한 업무를 2.0이 이어 갈 때 예산 한도 값이 없어 멈출 수 있는지 확인했는데, 1.0도 같은 값을 저장하므로 해당 없다.

| 끝난 업무의 결과 글·파일 | 읽힘(파일 5, 최종 3) | 읽힘(파일 5, 최종 3) |

전환·되돌리기에서 끝난 업무와 산출물은 양쪽 어디서나 보인다. 2.0에서 차례를 기다리던 건이 있는 채로 1.0으로 돌아가면 그 건은 1.0에서 스스로 시작되지 않는다(이번에는 대기 건이 없는 상태로만 확인했다).

## 5. 찾은 문제와 조치

1. **2.0 화면의 "끝난 대화에 이어 말하기"가 실제로는 실패했다(고침).** 서버는 1.0·2.0 모두 끝난 업무에 답글을 받지 않는다("이미 완료된 업무는 새 작업으로 지시해 주세요"). 2.0 화면은 끝난 대화에서 답글을 보내게 돼 있어 보내기가 거부됐다. 가짜 실행기 검사에 끝난 대화에서 실제로 보내 보는 확인이 없어 놓쳤다. 조치: 끝난 대화에서 보낸 말은 그 결과를 이어받는 새 업무로 접수한다(`after`). 화면 검사에 실제로 보내는 확인을 넣었고, 실제 Claude로도 확인했다.
2. **가이드 검색창에 한글을 치면 글자가 두 번 들어감(고침, 같은 날 대표가 발견).** 자동 검사는 입력란이 갈아 끼워지지 않는 것까지만 본다.

## 6. 이번에 확인하지 못한 것

- 실제 메일·카페 글·댓글 발송과 ERP 조회(금지 범위). 발송 직전 확인, 발송 결과 대조는 모의 발송기로만 봤다.
- 실제 회사 구성(부서 10개·고정 절차 6개)에서의 동작. 가상 부서 2개·직원 4명으로만 돌렸다. 고정 절차·예약·상시 감시·Aside 직원은 실제로 돌리지 않았다.
- Codex 엔진(검증실 포함). 이 PC의 codex 관련 테스트 3건은 양쪽에서 똑같이 실패한다.
- 화면을 사람이 직접 쓰는 흐름(실제 한글 입력기, 실제 휴대폰·태블릿).
- 표본 수. 업무 종류마다 한 번씩만 돌려 편차를 모른다.
- 2.0에서 대기·답변 필요 건이 남은 채 1.0으로 되돌리는 경우.
